# GOODProjects Grant Writer

A working reference for producing high-quality GOODProjects grant submissions fast, and for qualifying opportunities before time is spent on them. The detailed reference lives in **PLAYBOOK.md** (in this skill folder) — open it when drafting, reviewing, budgeting, or deciding whether to pursue an opportunity.

## The core principle (90 / 10)

GOODProjects submissions are **~90% stable boilerplate** (the canon: mission, need, programs, theory of change, equity, evaluation, staffing, partnerships). That part is reusable and is what makes drafting fast. **Award rate is won in the other 10% — the customization:** real budget figures, proof metrics matched to the funder's domain, a tailored executive summary, and a clean strip of machine artifacts and contradictions. Spend the time there.

## Workflow for any opportunity

1. **Qualify first** (PLAYBOOK Part 7). Geographic fit + program match + entity eligibility. If it fails any, flag it as a no-go to Neo before drafting. Several past submissions were forced fits that should never have been written.
2. **Build from the canon** (PLAYBOOK Part 2). Paste-and-trim the reusable sections.
3. **Customize hard** (PLAYBOOK Parts 3–4). Fill every real figure, pick funder-matched proof points, tailor the exec summary to this funder's language and priorities.
4. **Humanize the draft** (PLAYBOOK Part 8). Mandatory before export. Run the draft → audit → final loop: strip AI-writing tells (significance inflation, promotional puffery, "-ing" padding, vague attributions, copula avoidance, rule-of-three, synonym cycling, filler, chatbot framing, hedging disclaimers) and remove every em and en dash. If the standalone `humanizer` skill is enabled, load and run it for the full rule set; Part 8 carries the condensed, grant-adapted version so the core rules always apply even if it is not.
5. **Run the QA gate** (PLAYBOOK Part 6) before export. Mandatory, not optional — it now includes the humanize check.
6. **Deliver PDF alongside the editable source** (Word/Excel) every time.

## Non-negotiables (quick gate before anything leaves)

- **No unfilled placeholders.** Every `[X]`, `[INSERT]`, `TBD`, or blank is replaced with a real, verified figure. (~84% of past files shipped with these unfilled — the single most common defect.)
- **No machine artifacts.** Strip `internal_name`/`funder_language` tags, underscore slugs, Run IDs, and Drive-context appendices.
- **Numbers reconcile.** The headline ask equals the budget total; metrics don't contradict each other; the ask is within the funder's cap.
- **Dates are valid** and fall inside the project period (no completion-before-start, no malformed years).
- **Staffing roster is current.** Do not name the former "Cara Adams, Development Manager."
- **Attachments are uploaded files, not Google Drive links.**
- **Certifications are signed by the correct Authorized Official** and the typed name matches the signature.
- **Verify-before-reuse figures are confirmed against source** (see PLAYBOOK Appendix B) — e.g. $14,700 average income, "DC's #1 tutoring hub," "zero gun incidents," the address, the ward claim.
- **No AI-writing tells.** Run the humanize pass (PLAYBOOK Part 8): no significance inflation or empty superlatives, no vague attributions, no chatbot framing or hedging disclaimers, and no em or en dashes anywhere in the final text.
